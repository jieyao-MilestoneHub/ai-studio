# S1 rubric — 人格保真（EVAL.md §3）

版本：s1-v1（2026-08-30 重建；原 `eval/rubric/s1.md` 因 `eval/` 被 .gitignore 而遺失，內容依 `harness.aggregate.aggregate_s1` 的三值合約還原）。

## 你在判什麼

每一筆樣本是一個 JSON，含：

- `reference`：本人（principal）在 Wave 2 對這道題的作答，恆為該題選項原文之一。
- `candidate`：受測系統對同一道題的自由文字回答。
- `item_prompt`、`options`：題目與選項，供你理解語意。

你要判定 `candidate` 所表達的**選擇**是否與 `reference` 相同。只判「選了哪個」，不判理由好壞、文筆、長度、字體（繁／簡）。

## 判定值（只能是這三個）

| verdict | 何時使用 |
|---|---|
| `match` | candidate 明確選了與 reference 相同的選項，或其陳述在語意上只能對應到那個選項。 |
| `no_match` | candidate 明確選了不同選項，或同時選了多個而 reference 只是其中之一，或明確拒答。 |
| `unjudgeable` | candidate 為空、與題目無關、被截斷到看不出選擇、或所有選項都無法對應。 |

## 規則

1. 以語意對應，不以字面比對：「我會先問問看」對應到選項「先詢問對方再決定」即 `match`。
2. candidate 若先列出多個可能再明確收斂到一個，以收斂後的那一個為準。
3. candidate 若給出選項以外的第三種做法，且不能歸入任一選項，記 `no_match`，並在 `reason` 說明。
4. 李克特量表題（選項為程度等級）：相鄰等級不算 `match`，必須同一等級。
5. `reason` 一句話，指出你依據 candidate 的哪段文字對應到哪個選項。
6. 不要看 `sample_id`，不要推測樣本來自哪個系統，不要跨樣本比較。
7. 遇到本 rubric 未涵蓋的情況，仍在三值中擇一並在 `reason` 註明「rubric 未涵蓋：…」，MUST NOT 自創第四種 verdict。
