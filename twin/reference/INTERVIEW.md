## 1. 這份文件在做什麼

Onboarding 的第一步。目的是取得 `SPEC.md` §2.2 定義的**自陳資料**，它是孿生人格保真度的主要來源。

一句話說明它為何必要：**歷史資料告訴你這個人做了什麼，自陳資料告訴你他認為自己是誰。** 前者可以大量爬取，後者只能問。

## 2. 名詞定義（規範性）

本文件沿用 `SPEC.md` §2，並新增下列詞彙。

| 詞彙 | 定義 | 不是 |
|---|---|---|
| **採集階段 (Elicitation)** | onboarding 中取得自陳資料的整段流程，含訪談與問卷。 | 不是註冊。註冊不需兩小時。 |
| **訪談 (Interview)** | 半結構化、語音對語音、由 AI 訪談員主持的對話。 | 不是問卷朗讀。訪談員必須追問。 |
| **訪談大綱 (Schedule)** | 訪談員持有的主題與必達點清單。 | 不是逐字題本。題目順序與措辭由訪談員依現場調整。 |
| **必達點 (Required Coverage)** | 該區塊結束前 MUST 已取得的訊息。未達成則不得進入下一區塊。 | 不是題目。一個必達點可能由三個追問或一句話達成。 |
| **追問 (Follow-up)** | 訪談員針對受訪者剛才的回答即時生成的下一問。 | 不是大綱上的下一題。 |
| **具體事例 (Instance)** | 一個有時間、有地點、有結果的真實事件。 | 不是自我描述。「我很懶」不是事例，「上週三那封信我放到週日才回」是。 |
| **結構化問卷 (Survey)** | 固定題目、固定選項的量表。 | 不是訪談的替代品，是它的補項（見 §3.2）。 |
| **逐字稿 (Transcript)** | 訪談的完整文字紀錄，含受訪者與訪談員雙方發言。 | 不是摘要。摘要不可作為自陳資料。 |
| **連續訪談 (Continuous Session)** | 全部區塊於同一場次內不間斷完成。中途短暫休息 MAY 允許，但不得跨日或跨小時級中斷。 | 不是「同一天內分兩段」。 |
| **補問 (In-session Probe)** | 訪談員於**同場次內**發現必達點未達成而追加的提問。 | 不是補訪。 |
| **補訪 (Re-interview)** | 訪談結束後另約時間補採集。**本規格已排除（§8 I-C）。** | — |

## 3. 研究依據

### 3.1 時長與連續性（已裁決）

依據 Park et al., arXiv:2411.10109：該研究對 1,052 名受訪者進行**兩小時、半結構化、語音對語音**的訪談，採用 American Voices Project 的訪談大綱，平均逐字稿長度為 **6,491 words**（英文，std = 2,541）。由此建立的 agent 在 held-out 的 GSS 題目上達到受訪者自我一致性的 83%。

**本規格裁決：**

| 項目 | 規格 |
|---|---|
| 時長 | **連續 102 分鐘**（1.7 小時） |
| 連續性 | **MUST 為單一場次。MUST NOT 分段。** |
| 逐字稿長度 | **≥ 5,500 字**（繁體中文） |

裁決理由：分段會損害敘事連貫性。區塊 A 的人生敘事與區塊 B 的行為事例之間存在互相召回的效果，跨場次會失去。

**單位差異須知悉**：原研究的 6,491 是英文 **words**，本規格的 5,500 是中文**字**，兩者不是同一單位。單一中文字所承載的資訊量低於單一英文 word，故就等量資訊而言，5,500 字**可能偏低**。本規格仍採此值，但將字數定位為輔助指標，時長為主。

**時長與字數衝突時的處置**：

- 102 分鐘為**下限**，非上限。
- 若 102 分鐘屆滿而字數未達 5,500，MAY 於**同一場次內**延長至多 120 分鐘。連續性不得因此破壞。
- 延長後仍不足者，MUST 依 §7 標記為低信心，MUST NOT 另約補訪。

### 3.2 為什麼訪談與問卷都要做

同研究的三組對照（v3 數據，對 held-out GSS 題目，以受訪者自我一致性正規化）：

| Agent 來源 | 正規化準確率 |
|---|---|
| 只用訪談逐字稿 | 83% |
| 只用結構化問卷 | 82% |
| **兩者合併** | **86%** |

兩者單獨使用表現接近，**合併後顯著較佳**。且兩者皆優於以人口屬性或一段自我描述建立的 agent。

**因此本規格裁決：採集階段 MUST 同時包含訪談與結構化問卷。** 只做其中一項會損失約 3–4 個百分點的保真度，而多做問卷的成本僅約 15 分鐘。

### 3.3 為什麼是半結構化而非問卷式

AVP 大綱的開場是請受訪者「說說你的人生故事」，其後以開放式提示涵蓋工作、家庭、健康、教育、消費、政治等生活領域。

開放式敘事之所以優於屬性描述，是因為它產生**本人自己的措辭、自己的因果解釋、自己選擇要講什麼**。最後一項尤其重要：受訪者主動提起的內容，依定義即為對本人重要的內容，這個訊號直接餵給 `SPEC.md` §4.6 的 salience 計算，成本為零。

## 4. 訪談結構

總長 **102 分鐘**，四個區塊，單一連續場次。時間為建議配置，訪談員 MAY 在總長不變的前提下於區塊間調整，但**必達點 MUST 全數涵蓋**。

因已排除補訪（§8 I-C），**訪談員於同場次內的補問是唯一的補救窗口**。時間分配的優先順序為：B > A > C > D。

### 區塊 A — 人生敘事（42 分鐘）

改編自 AVP 大綱。目的是建立人格與價值觀的基底，服務 `EVAL.md` S1 的價值取捨與偏好題型。

開場語 MUST 為開放式：「請跟我說說你的人生故事，從哪裡開始都可以。」

生活領域涵蓋：成長背景、工作、家庭與關係、健康、教育、金錢與消費、社群與政治參與。

**必達點：**

- A1 至少三個人生轉折點，各含時間、當時的選項、選擇的理由
- A2 至少兩次「後來覺得當初選錯」的事例
- A3 本人如何描述自己與他人的差異
- A4 本人明確在乎與明確不在乎的事各兩項，各附一個事例

### 區塊 B — 行為政策（36 分鐘）

AVP 大綱不涵蓋此區塊。這是為本專案新增的部分，服務 `EVAL.md` S2 與 S3——也就是孿生要能自動回訊息、自動查資料、主動發文所需的決策依據。

本區塊 MUST 以具體事例驅動。「你是個怎樣的人」類的自我描述 MUST 被追問至事例層級。

**必達點：**

| # | 必達點 | 服務 |
|---|---|---|
| B1 | 三個「本來想回但沒回」的具體事例，含當下的理由 | S3 硬負例、silence_rate |
| B2 | 三個「本來不必回但回了」的具體事例 | S3 |
| B3 | 遇到不確定的事，查或不查的分界在哪；一個查了的例子與一個沒查的例子 | S2b |
| B4 | 查了但查不到時，第幾次放棄；一個放棄的例子 | S2b 放棄點 |
| B5 | 什麼樣的內容會讓本人主動想發言；最近一次是什麼 | S3 |
| B6 | 什麼樣的內容本人有感觸但決定不發；最近一次是什麼 | S3 硬負例（**本區最難也最重要的一題**） |
| B7 | 本人主動推薦別人使用的東西，以及推薦的方式 | 人格特徵 |
| B8 | 對不同對象（家人／同事／陌生人）的回覆速度與語氣差異 | S1、S4 |

B6 的重要性單獨說明：`SPEC.md` §4.3 指出歷史資料中的曝光紀錄通常已遺失，因此**訪談是取得早期硬負例的唯一來源**。若 B6 只拿到一個模糊回答，S3 在曝光採集上線前將沒有可用的負例。訪談員 MUST 在此追問至三個具體事例。

### 區塊 C — 記憶抽樣（16 分鐘）

目的有二：驗證記憶層的可檢索性，並取得本人自然的時間模糊度表述，服務 `EVAL.md` §3.5 的模糊度匹配。

**必達點：**

- C1 針對三個不同時期各回憶一件事，訪談員 MUST NOT 提示精確日期
- C2 記錄本人自然使用的時間表述（「大概去年夏天」「疫情那陣子」），逐字保留
- C3 至少一次本人明確表示「記不清楚」或「可能記錯」的情況

C2 MUST 逐字保留而非正規化為日期。這些表述本身就是要被學習的目標。

### 區塊 D — 收束（8 分鐘）

- D1 「有什麼是我沒問到、但你覺得要理解你就必須知道的？」
- D2 「如果有個東西要代替你回訊息，你最不希望它做什麼？」

D2 的回答 MUST 被記錄為孿生的負向約束，並於 `EVAL.md` S4 盲測的判斷理由中對照檢查。

## 5. 結構化問卷（15 分鐘，訪談後）

於訪談結束後施測，MUST NOT 於訪談前施測。

理由：問卷的固定選項會定錨受訪者的自我表述，使其後的開放敘事向選項靠攏，損失自陳資料的獨有價值。

內容 SHOULD 包含：

- 人格量表（Big Five 或同等）
- 一般社會態度題組（可取材自 GSS，但 MUST 與 `EVAL.md` S1 的題庫**互斥**）
- 本人在各 surface 的自估回應率與回應延遲

最後一項是 `EVAL.md` §5.5 `silence_rate_delta` 的參考值來源之一。

## 6. 執行規格

| 項目 | 規格 |
|---|---|
| 語言 | **台灣華語口語**；逐字稿為繁體中文。中英混用 MUST 逐字保留，MUST NOT 翻譯或統一 |
| 形式 | 語音對語音，AI 訪談員主持 |
| 訪談員 | Teacher 模型（Gemini Flash 免費層，含多模態輸入） |
| 分段 | **MUST NOT 分段。**單一連續場次，102–120 分鐘 |
| 產出 | 完整逐字稿（雙方發言）+ 音檔 |
| 音檔 | 依 `SPEC.md` §7.2，MUST NOT 上傳至跨雲儲存。**MUST 保留至逐字稿通過 §7 檢核為止**，MUST NOT 於轉錄後立即刪除 |
| 逐字稿 | `source_class: "self_report"`，掛於記憶層 Period 級，且 MUST 可原文還原（`SPEC.md` D26） |

### 6.1 訪談員行為規範

- MUST 對每個必達點追問至具體事例層級。
- MUST NOT 接受單一形容詞作為必達點的達成（「我很懶」不算 B1 達成）。
- MUST NOT 誘導。追問 MUST 為開放式，MUST NOT 提供選項。
- SHOULD 在受訪者岔題時容許其講完；岔題內容往往即高 salience 內容。
- 每區塊結束前 MUST 自我檢核必達點，未達成者 MUST 於**同場次內**補問。
- 補問是唯一補救窗口（§8 I-C 已排除補訪）。訪談員 MUST 在區塊剩餘時間內完成補問，MUST NOT 將未達成項留到訪談後處理。

### 6.2 逐字稿後處理（依 §8 I-A 裁決）

語音管線的品質問題**於資料處理階段解決**，不作為訪談前的阻塞條件。訪談照常進行，轉錄結果再修。

MUST 執行的後處理：

1. **專有名詞校正**：人名、地名、公司名、技術詞彙是 ASR 錯誤集中處。MUST 以本人既有資料（聯絡人、既往訊息）建立詞表後校正。
2. **中英混用還原**：ASR 常將英文詞轉寫為近音中文。MUST 檢查並還原，因為混用比例本身是評測項（`EVAL.md` §8.4）。
3. **口語保留**：語助詞、重複、停頓 MUST 保留。它們是措辭風格的一部分，MUST NOT 「順稿」。
4. **不確定標記**：無法確定的段落 MUST 標記為 `[unclear]`，MUST NOT 猜測填補。

後處理 MUST 可重跑：詞表更新後能重新產生逐字稿，這是音檔須保留至檢核通過的原因。

已知風險（已接受）：ASR 錯誤會直接污染自陳資料，而自陳資料是 S1 保真度的主要來源。緩解手段僅有上述後處理與音檔保留；本規格不再要求事前試錄。

### 6.3 第三方內容

訪談必然涉及第三方（家人、同事）。逐字稿 MUST 依 `SPEC.md` §4.9 標註 `third_party_spans`。

**§11-C 裁決前，逐字稿 MUST 留存於本機，MUST NOT 進入跨雲儲存。** 訪談本身可以進行，處置延後。

## 7. 品質檢核

依 §8 I-C 裁決，**不補訪**。因此檢核的作用由「觸發補採集」改為「決定下游可信度」。

採集完成後 MUST 執行檢核。未通過項 MUST 記錄於採集報告，並依對照欄標記對應 evaluation suite 為**低信心**（`EVAL.md` §6.4 的低信心規則同樣適用：低信心輪次 MUST NOT 用於閘門升級）。

| # | 檢核項 | 未通過的處置 |
|---|---|---|
| Q1 | 全部必達點已涵蓋 | 對應 suite 標記低信心 |
| Q2 | B1／B2／B6 各至少三個具體事例 | **S3 標記低信心**，且在曝光採集上線前 S3 MUST NOT 用於閘門判定 |
| Q3 | 單一連續場次，時長 102–120 分鐘 | 整體標記低信心 |
| Q4 | 逐字稿 ≥ 5,500 字 | 整體標記低信心 |
| Q5 | 受訪者發言占比 ≥ 70% | S1 標記低信心 |
| Q6 | C2 時間表述已逐字保留 | `EVAL.md` §3.5 模糊度匹配項不計分 |
| Q7 | 問卷於訪談後施測 | S1 標記低信心 |
| Q8 | `third_party_spans` 已標註 | MUST 阻擋：未標註前逐字稿 MUST NOT 進入記憶層 |
| Q9 | §6.2 後處理四項已執行 | `EVAL.md` §8.4 語碼轉換項不計分 |

**Q8 是唯一的硬阻擋項。** 其餘皆為標記，不阻擋流程——這是「不補訪」裁決的直接後果：品質不足時我們接受較低的信心，而不是重來。

Q5 是最容易失守的一項。AI 訪談員傾向解釋與總結，SHOULD 於 prompt 中明確抑制。因無補訪機制，訪談員 MUST 於每區塊中段自我檢核發言占比。

## 8. 裁決紀錄

2026-08-27 全數裁決，無開放項。

### I-A. 訪談語言與語音管線 → **已裁決：台灣繁中為主，品質問題於資料處理階段解決**

不做事前試錄，不因語音品質阻塞訪談。衍生規格：§6.1 語言列、§6.2 逐字稿後處理、音檔保留至檢核通過。

風險已明示並接受（§6.2 末段）。

### I-B. 分段是否影響品質 → **已裁決：有影響，採連續 1.7 小時**

連續 102 分鐘、單一場次、逐字稿 ≥ 5,500 字。衍生規格：§3.1、§4 區塊時間重配為 42/36/16/8。

已記錄的疑慮：5,500 中文字與原研究 6,491 英文 words 非同一單位，可能偏低。故字數為輔助指標、時長為主，且允許同場次內延長至 120 分鐘（§3.1）。

### I-C. 補訪的觸發與上限 → **已裁決：不補訪**

衍生規格：§7 檢核由阻擋制改為標記制，僅 Q8 為硬阻擋；§6.1 同場次補問成為唯一補救窗口；§4 新增時間分配優先序 B > A > C > D。

實質後果：品質不足時我們接受較低的信心，而非重來。這使**訪談員的即時檢核能力**成為採集品質的單點決定因素。

### I-D. 他人使用時的訪談同意流程 → **已裁決：不實作**

與 `SPEC.md` §11-C 一致：本專案為個人自用之開源工具，非產品，不代管他人資料。責任歸屬由 README 聲明（`SPEC.md` §8 護欄 3）。

**須知悉**：訪談逐字稿必然含第三方可識別內容（家人、同事的姓名與事件）。由於不實作同意流程與匿名化，§6.3 的「逐字稿 MUST 留存本機、MUST NOT 進入跨雲儲存」從一般規定升格為**承擔全部第三方風險的關鍵路徑**。它與 `SPEC.md` §8 護欄 2 的 pre-commit hook 是僅存的兩道防線。
